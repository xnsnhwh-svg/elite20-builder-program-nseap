# Knowledge Cognitive Cell v0.1 到 v0.2 进展说明与下一步计划

## 一、项目定位

本项目是 NSEAP 第 6 模块 Knowledge Cognitive Cell 的 MVP。它的目标不是简单做一个资料文件夹，而是验证一套可以持续沉淀课程、挑战、项目案例、提示词、FAQ 和 Agent 上下文的知识管理能力。

v0.1 主要验证“知识库应该如何展示和检索”。v0.2 开始验证“真实资料进入系统后，能否被保存、分类、搜索、编辑和管理”。

## 二、v0.1 原有能力

v0.1 是一个静态前端 Demo，主要实现了以下能力：

- 展示知识库首页、浏览页和知识详情页。
- 按课程、挑战、项目案例、提示词、FAQ、Agent 等类型筛选知识。
- 支持关键词搜索。
- 展示每条知识的 metadata，例如关键词、概念、技能、适用对象。
- 展示知识增长流程：场景、本体、流程、技能、评估、学习、知识增长。
- 展示知识之间的显式关系和 Agent 检索视角。

v0.1 的价值是把产品形态和知识模型先做出来，方便讨论模块定位和演示核心概念。但它的问题也比较明显：数据主要是固定在静态文件里，不能完整验证上传、入库、编辑、删除和模型配置这些真实工作流。

## 三、v0.2 已完成的主要升级

### 1. 从静态 Demo 升级为轻量前后端 MVP

v0.2 增加了 Node.js 后端服务。前端不再只依赖固定静态数据，而是通过 API 读取后端数据。

当前演示入口：

```text
http://127.0.0.1:8787/index.html
```

启动方式：

```bash
npm run dev
```

### 2. 增加本地 JSON 数据库

知识条目现在保存到本地数据库文件：

```text
data/knowledge-db.json
```

这意味着知识条目不再只是页面里的固定展示内容，而是可以被后端读取、写入、修改和删除。

### 3. 增加文件上传生成知识草稿

v0.2 增加了文件上传入口。用户可以上传资料，系统会：

- 保存原始文件到 `data/uploads/`。
- 自动生成一条 `draft` 状态的知识草稿。
- 把草稿写入 `data/knowledge-db.json`。
- 上传后可以在浏览页中搜索和查看该草稿。

这一步验证了“真实资料进入知识库”的基本链路。

### 4. 增加 metadata 在线编辑

上传或新增后的知识草稿，可以在详情页继续补充：

- 关键词
- 概念
- 技能
- 适用对象
- 审核状态

这对应正式知识库里的“资料进入系统后，需要被结构化整理和审核”的过程。

### 5. 增加 LLM 自动分类接入口

v0.2 在右上角设置面板中增加了模型配置能力：

- Base URL
- 模型名称
- API Key

配置后，系统可以在上传可读取文本的文件时调用 LLM，自动生成类型、摘要、关键词、概念、技能和适用对象。

当前能力边界：

- `.txt`、`.md`、`.csv`、`.json` 这类文本文件可以直接读取正文并尝试 LLM 分析。
- `.docx` 已支持从 Word 文档 XML 中抽取正文，再交给 LLM 或规则分类。
- `.pdf` 已支持基础文本流抽取；扫描版 PDF 或复杂编码 PDF 后续需要接入 OCR 或更专业的 PDF 解析器。

### 6. 优化 metadata-first 搜索逻辑

搜索不再只是模糊扫全文，而是优先匹配结构化 metadata：

- `keywords`
- `title`
- `type`
- `tags`
- `concepts`
- `skills`
- `audience`

这样搜索“挑战”时，会优先返回真正被标注为挑战或关键词包含挑战的条目，而不是随便返回正文里出现相关词的内容。

### 7. 将删除升级为归档机制

浏览页右侧详情区新增了归档按钮。为了避免误删，当前不再硬删除数据库记录，而是：

```text
点击归档图标
-> 显示确认框
-> 点击确认归档
-> 后端把知识条目状态改为 archived
-> 前端列表和默认搜索结果同步移除
-> 后端详情仍然保留，后续可恢复或审计
```

这借鉴了正式知识库的治理思路：不轻易丢失资料，先下架、归档，再决定是否恢复或清理。

### 8. 增加显式关系管理

详情页已经可以维护知识之间的显式关系。用户可以选择当前条目与其他条目的关系，例如：

- `supports`：项目案例支持某个挑战。
- `requires`：一个任务需要某个前置知识。
- `usesPrompt`：一个挑战或案例使用某个 Prompt。
- `relatedTo`：两个知识条目相关。

后端对应新增：

```text
GET  /api/knowledge/:id/relationships
POST /api/knowledge/:id/relationships
```

这一步让知识不只是“能被搜索”，还开始具备知识图谱和 Agent 检索需要的连接结构。

### 9. 增加设置面板和界面主题切换

右上角新增设置面板，包含：

- 模型配置
- API Key 配置状态
- 前端色系切换

这让演示时可以说明：当前系统已经预留模型接入和运行配置入口，后续可以继续扩展为更完整的知识工作台。

### 10. 增加三步上传工作流

新增页现在按照更接近正式产品的流程组织：

```text
上传资料
-> 系统抽取正文并生成草稿
-> 人工检查 metadata、关系和状态
```

上传成功后，页面会直接进入该草稿的详情页，方便继续检查分类、补充关键词、建立关系并进入审核。

### 11. 增加老师带练入口

浏览模块不再只是让用户自己看资料，而是提供“开始带练”入口。用户打开一条知识后，系统会根据知识类型和显式关系生成学习路径，每一步包含：

- 老师式讲解
- 当前知识卡片
- 小检查问题
- 下一步行动按钮

当前版本先使用规则模板生成路径，保证没有 LLM Key 也能演示完整流程。后续提供 API Key 后，可以把每一步的讲解和小检查升级为 LLM 动态生成，让带练内容更贴合具体资料。

### 12. 增加知识图谱和搜索悬浮预览

浏览页新增“列表 / 图谱”切换。列表模式下，鼠标悬浮在搜索结果上会出现预览卡，用户不用进入详情也能快速判断这条知识是否相关。图谱模式下，系统把知识条目展示为节点，把显式关系和关键词浅关联展示为连线，方便快速看到知识之间的联系。

后端同步增加：

```text
GET /api/knowledge-graph
```

这个接口返回图谱节点、连线和统计信息，为后续正式知识图谱、Agent 检索和关系可视化打基础。

## 四、当前 v0.2 能演示的完整链路

当前 MVP 已经可以演示：

```text
上传资料
-> 后端保存文件
-> 抽取 docx/pdf/文本正文
-> 生成知识草稿
-> 写入本地数据库
-> 前端读取数据库
-> 按 metadata 搜索
-> 悬浮预览搜索结果
-> 打开知识详情
-> 补充 metadata
-> 维护显式关系
-> 切换知识图谱查看关联
-> 点击开始带练
-> 按步骤理解并复用知识
-> 必要时归档知识条目
```

这说明项目已经从 v0.1 的“静态展示”，升级为 v0.2 的“轻量可操作知识库”。

## 五、下一步计划

每次迭代结束后，先用 `docs/iteration-self-checklist.md` 做一次产品自查，再决定下一步优先级。重点不要只问“做了什么功能”，而要问“目标用户是谁、给用户带来什么价值、用户能否更快达到产品目标”。

### 下一步 1：接入 LLM 生成带练内容

当前老师带练已经跑通规则模板版本。下一步需要在你提供 LLM API Key 后，把 `teacherScript` 和 `checkQuestion` 改为模型生成，同时保留规则模板作为兜底，避免模型不可用时影响演示。

### 下一步 2：增强 PDF / OCR 正文抽取

当前已经支持 `.docx` 正文抽取和基础 PDF 文本流抽取。下一步可以增强扫描版 PDF、图片型 PDF 和复杂编码 PDF 的解析能力，必要时接入 OCR。

### 下一步 3：优化 LLM 分类结果

接入 LLM 后，需要继续优化提示词和输出标准，让模型稳定返回：

- 知识类型
- 一句话摘要
- 关键词
- 概念
- 技能
- 适用对象
- 置信度

同时要保留人工修改能力，避免模型分类不准确时无法纠正。

### 下一步 4：增加回收站和恢复入口

当前 MVP 已经把删除升级为归档。后续可以继续增加回收站和恢复入口，使状态流更完整：

```text
active
draft
review
archived
deleted
```

这样用户可以查看已归档条目、恢复误归档内容，并保留更完整的审计记录。

### 下一步 5：增加知识审核流程

后续可以把知识条目分成：

- 草稿
- 待审核
- 已发布
- 已归档

这样可以更符合 Knowledge Team 的工作方式：资料先进入系统，再由人或 Agent 辅助整理，最后审核发布。

### 下一步 6：为 Agent 检索准备接口

当前页面已经展示 Agent 检索视角。下一步可以增加专门的 Agent API，例如：

```text
GET /api/agent/context?q=...
```

让 Agent 可以按关键词、技能、概念和任务场景检索知识，而不只是给人看。

### 下一步 7：准备 GitHub 提交与汇报材料

后续需要整理：

- MVP 代码
- 设计文档
- 进展说明
- 演示截图
- README 启动说明

然后提交到 fork 仓库对应目录，方便老师和同学 review。

## 六、汇报时可以这样总结

v0.1 解决的是“知识库长什么样、怎么组织知识”的问题。v0.2 解决的是“真实资料进入系统后，能不能被保存、分类、搜索、编辑、管理，并被用户快速理解和复用”的问题。

目前系统已经跑通了一个更接近正式使用的轻量知识库 MVP：可以上传资料、抽取 Word/PDF 正文、生成草稿、补充 metadata、维护显式关系、按 metadata 搜索、悬浮预览知识、查看知识图谱、配置 LLM、归档知识条目，并通过“老师带练”把知识浏览转成学习路径。下一步重点是在你提供 LLM API Key 后升级带练讲解和自动分类能力，同时增强复杂 PDF/OCR 解析，并补充回收站与审核发布流程。
